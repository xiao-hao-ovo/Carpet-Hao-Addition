## 1. Repository layout

```
Carpet-Hao-Addition/
├─ src/main/java/            shared source, 28 files (used by every version)
├─ src/main/resources/       shared resources (lang must live here)
├─ versions/                 8 layers for 1.21.x: 1.21, 1.21.1, 1.21.10, 1.21.11, 1.21.2, 1.21.4, 1.21.6, 1.21.8
│    └─ <version>/src/main/java/   full implementation for that layer (~70+ files)
├─ modern/                   3 layers for 26.x: 26.1.2, 26.2, 26.3 (built separately)
├─ docs/                     documentation
└─ tools/                    build and release scripts
```

### Build model: shared + override

`versions/<version>/build.gradle` compiles **two** source roots together:

```groovy
sourceSets.main.java.srcDirs = [
    rootProject.file('src/main/java'),   // shared: rule settings, command entry points
    file('src/main/java')                // this layer: the actual implementation
]
duplicatesStrategy = EXCLUDE             // same-named file is replaced wholesale
```

So there are only two kinds of files:

| Kind | Lives in | Meaning |
|---|---|---|
| **Shared** | `src/main/java` | rule settings, commands, cross-version helpers. One copy for all versions |
| **Per-layer** | `versions/<version>/src/main/java` | APIs differ per version, so each layer has its own |

> ⚠️ Resources such as `lang` **must** go in the shared `src/main/resources`.
> Putting them inside a layer does not merge keys — it replaces the whole file,
> dropping every other key from the shared copy.
