## I. Repository layout

```
Carpet-Hao-Addition/
├─ src/main/java/            shared sources, 27 java (used by every version)
├─ src/main/resources/       shared resources (lang MUST live here)
├─ versions/                 8 layers for 1.21.x: 1.21, 1.21.1, 1.21.10, 1.21.11, 1.21.2, 1.21.4, 1.21.6, 1.21.8
│    └─ <version>/src/main/java/   that layer's full implementation
├─ modern/                   3 layers for 26.x: 26.1.2, 26.2, 26.3 (built separately)
├─ docs/                     documentation
└─ tools/                    build and publish scripts
```

### Build model: shared + override

`versions/<version>/build.gradle` compiles **two** source roots together:

```groovy
sourceSets.main.java.srcDirs = [
    rootProject.file('src/main/java'),   // shared: rule settings, command entry points
    file('src/main/java')                // this layer: full implementation
]
duplicatesStrategy = EXCLUDE             // same-named file replaces wholly
```

So there are only two kinds of file:

| Kind | Location | Notes |
|---|---|---|
| **Shared** | `src/main/java` | Rule settings, commands, cross-version helpers. One copy for all versions |
| **Layer** | `versions/<version>/src/main/java` | APIs differ per version, so each layer implements its own |

> ⚠️ Resources such as `lang` **must** go in the shared `src/main/resources`.
> Placed inside a layer they are **wholesale replaced** rather than merged by key,
> which silently drops the other keys.
